### 0.2 每一节的固定结构（按顺序）
1. **学习目标** `objectives`：4–5 条，关键概念写成 `**中文 (English)**`
2. **第一个文字块**：`### 先说这一节要干什么`——为什么学；`**学完它你就能看懂这几件事：**`（3–4 条，要落到机器学习 / PyTorch / 真实代码的具体场景）；`**本节安排（约 N 分钟）**：…`（把时间拆到每一小段，含视频）
3. **每个新概念**：先放引用块，格式如下，再紧接一段 `**白话版：「一句话比喻」。**`（例子、类比、先给直觉），然后是代码和「读输出」：

```
> **标准定义 · 中文 (English)**
>
> 定义正文（中文，严谨，含公式）
>
> *English: 一两句英文定义*
```

4. **代码**：带逐行中文注释；**「# 输出：」行由 `runlib.code()` 运行后自动写入**，不要手写；代码后面要有一段「读输出」，**文字里的数字必须和输出完全一致**（写完把正文里的数字和输出对一遍）
5. **视频块** `V(...)`：放在对应的文字块之后，每节 2–4 个，合计约 20–40 分钟；太长的视频放进参考资料作为「选看」
6. `### 这一节你要带走的三句话`：编号 1–3
7. **3 个「想一想」** `THINK`：一道计算 / 实践题、一道概念辨析、一道和机器学习或后续内容的联系；答案要完整
8. **关键词表** `KW`：12–15 个，`(中文, English, 一句话说明)`
9. **参考资料**：3–5 条，第一条是内容依据的大学课程或开放教材（**只引用不转载**）；选看的长视频放这里
10. **测验 10 题**：规则同后面「五、出测验」；**解释里不要写「选项 3」「第二项」这类位置引用**（选项顺序会被调整）；用 `TARGET` 列表和交换选项的小循环来调整答案位置（见任何一个 `tools/course/d*.py` 的末尾）

**每节时长**：70–120 分钟（视频 + 阅读 + 动手），写进 `minutes`，`course.json` 同步。

### 0.3 渲染规则（页面用 marked + KaTeX，踩过的坑）
- `$...$` 行内公式**必须在同一行**（渲染器用 `\$[^$\n]+?\$` 保护公式，跨行会失效）；`$$...$$` 显示公式放在**单独一行**；引用块里的显示公式也必须在**一行内**写完
- 公式里的中文要用 `\text{}`；在 Python 里文字块用 `r"""..."""`，普通字符串（`KW`、`Q`、`THINK` 的题目）里反斜杠要写两个（`\\sigma`）
- 代码块里**不要有同一行出现两个以上 `$`**
- 表格、引用块、代码块都是标准 Markdown；列表前要有空行

### 0.4 脚本写法（每节两个文件）
- `tools/course/<课>NN.py`：这一节的内容，`T(r"""…""" + C_XXX + r"""…""")` 把代码块拼进文字；末尾 `dump(unit, "<课目录>", "<文件名>.json")`。课代号：`p`=prob-0，`d`=dsa-0，`y`=py-0，`a`=arena-0.0
- `tools/course/<课>NNc.py`：这一节的代码块，`C_XXX = code('''…''')`（`code` 来自 `runlib.py`）。`code(src, err=True)` 会把标准错误并进输出（用来展示 traceback、日志）
- **已知的坑**：写完文件后必须运行 `sed -i 's/^""") + C_/""" + C_/' 文件.py`（把行首的 `""") + C_` 改成 `""" + C_`，否则 `SyntaxError: closing parenthesis ')' does not match opening parenthesis '['`）
- 代码块**只用标准库**；ARENA 的节可以用 NumPy。Yijia 电脑上的 Linux 虚拟环境是 Python 3.10 + numpy 2.2，**没有 torch**，所以要用 PyTorch 的代码块不能让 `code()` 直接运行：先装到临时环境，或者标明「不运行」并手动核对
- 计时类输出（`time.perf_counter`）正文里只写量级，具体倍数每台机器不同；带内存地址的输出（`<zip object at 0x…>`）要改成 `type(x).__name__`
- 项目类的节（如 `y06c.py`）：把项目文件作为字符串写进临时目录，真的运行，把终端输出收集起来再嵌进正文，保证正文和实际运行结果一致

### 0.5 质量要求（每一节都要做）
- **随机对拍**：算法类代码用随机输入和暴力解法（或标准库）比较，输出一行 `True`（比如 Dijkstra 对 Floyd-Warshall、背包对子集枚举）
- 正文里的结论要和输出一致：写完读一遍，不一致就改文字（出过的错：均摊分析的数字、堆 push 的过程讲解、哈希探测的统计、一个以为「会出错」其实没出错的负权边例子）
- 不确定的事实不要写；视频用 `yt.py verify` 核实，**没看过内容就只能说是按标题和时长选的**，交付时要告诉她
- 检查：`python tools/course/<课>NN.py`（自动检查测验和公式配对）→ `python tools/course/validate.py --online`（联网核实视频和链接；偶尔因网络超时失败，重跑即可）→ `npm test` → 把所有公式用 KaTeX 试渲染（抽取用的正则同渲染器，0 个出错才算过）→ 确认讲义里没有写作提示类文字

### 0.8 代码块：一个知识点一段、解释紧跟、网页里可以运行（2026-10-05 起）
网页的学习页里，每个 ```python 代码块会变成一个像 Jupyter 的单元：有「▶ 运行」，能改代码再跑，**同一节里前面的块定义的变量，后面的块能直接用**；块末尾的 `# 输出：` 行显示成「预期输出」，点运行后换成这次的结果（`js/study/runner.js`、`pyworker.js`，浏览器里的 Python 是 Pyodide，第一次点运行要下载约 10 MB，之后缓存）。所以写代码块要遵守：
- **一个块只讲一个知识点**，不超过 **35 行**（不算输出行）。`validate.py` 对 `py-0` 超过会报错，对其他课只提示。一整段「大杂烩」要拆开
- **顺序固定**：一两句引入（这段代码要回答什么问题）→ 代码块 → **紧跟着**「读输出」解释这一块，再讲下一个知识点。不要先放一大段代码、后面再用编号逐条解释
- 出课脚本里用 `Notebook`：`nb = Notebook()`，每个块 `C_X = nb.cell('''...''')`。**块在 `xNNc.py` 里的定义顺序必须和讲义里出现的顺序一致**（出课时是按定义顺序依次运行的，后面的块可以用前面的变量）。`runlib.code()` 仍可用，但每块各自独立运行、不共用变量，新写的 py-0 一律用 `Notebook`
- 规则和网页一致：整块运行；**最后一行如果是表达式，会像 Jupyter 一样把它的值打印出来**；故意展示报错的块用 `err=True`（报错信息也会写进输出）
- 网页里跑不了的块（真实读写磁盘上的项目文件、启动子进程、`pip` / `venv` / `git`、需要 `torch` / `matplotlib` 的）用 `static=True`，生成 ` ```python-static `，只显示、没有运行按钮；出课时仍然真实运行并写入输出。后面的运行块**不要依赖** static 块里定义的变量
- 不要用 `input()`（网页里不支持）；伪代码、命令行输出不要写成 ```python，用 ```text / ```bash
- 网页里可以用 `numpy`（自动加载），没有 `torch` / `matplotlib`；块里的耗时、随机数要固定种子或只输出不依赖机器的结果

### 0.9 每个小节不超过 50 分钟（2026-10-06 起）

Yijia 的要求：一节 100 分钟太长、没有成就感，**每个小节 ≤ 50 分钟**。`validate.py` 会对超过 50 分钟的节报错。

做法：先按 v3 把一整节写完（`yNN.py` 等照旧，`dump` 出整节 JSON），把整节 JSON 复制到 `tools/course/whole/<课程>/`，再运行 `python3 tools/course/split.py <课程> [节号…]`：
- 在 `###` 小节边界和「读输出」段落之后切开，第一个小节沿用原 id（进度按 `课程__节id` 记，所以原 id 不能变），后面的叫 `u01b`、`u01c`……；标题加「（1/3）」；`course.json` 里这些条目带 `whole`（整节文件名）和 `part_of`
- 「想一想」、关键词、测验按相关度分到各小节，每个小节 2–5 道测验，正确答案位置打散；参考资料放最后一个小节
- 后面的小节用到前面小节定义的变量时，自动在开头补一个「承接上一小节」的代码块（网页里每进入一节都会清空变量）
- **要改内容时改整节（`yNN.py` / `whole/` 里的 JSON），再重新运行 split.py**，不要直接改拆出来的小节文件，否则下次拆分会覆盖
- 整节 id 不变；拆分后跑 `validate.py`，并在浏览器里抽测几个小节的运行块

**测验题干里考代码结果时**（Yijia 2026-10-06 提的）：必须把完整代码单独放进 ```text 围栏里（用 `text` 不用 `python`，避免出现运行按钮），要用 `print(...)` 写明打印什么，不要用文字描述代码（「两次返回值打印出来」这种说法有歧义）；题干里的代码要自成一体，不依赖别的题。

### 3. 写内容（每节固定结构）
复制 `tools/course/unit_template.py` 成 `tools/course/uXX.py` 再写。每节依次包含：

1. **学习目标** `objectives`：3–4 条「学完这节你能……」
2. **导读**：为什么学（ARENA 原文怎么说、后面哪里会用到）+ **本节时间安排**
3. **视频 → 要点** 交替：要点对照视频，用自己的话、分点、带公式；不要只是复述视频标题
4. **补充讲解**：视频没覆盖、但原文要求的知识点（比如转置 / 迹没有好视频，就用文字写）
5. **3 个「想一想」**：最好是一道计算题、一道概念辨析、一道和深度学习 / ARENA 后续内容的联系
6. **关键词表**：8–12 个，中文 / English / 一句话说明
7. **参考资料**：第一条是 ARENA 原文对应部分，其余是原文推荐的读物、官方文档

**写法细节**
- 公式：`$...$` 行内、`$$...$$` 单独一行（KaTeX 渲染）。在 Python 脚本里用 `r"""..."""` 原始字符串写，JSON 里反斜杠会自动变成两个
- 表格、代码块用标准 Markdown
- **代码块里注释写的输出，必须是真的跑出来的**（见第 4 步）
- 和后续内容建立联系：比如「这就是 ARENA 第 1 章实现多头注意力时要写的代码」

### 4. 跑代码、算数字
- 所有代码示例、测验里的数字（形状、计算结果）都要**实际运行**确认。2026-09-28 用的环境：Python 3.12 + numpy 2.5 + torch 2.14 (CPU) + einops 0.8，装在一个短路径的虚拟环境里（Windows 路径太长 torch 会装失败）：
```bash
python -m venv %TEMP%\qlv
%TEMP%\qlv\Scripts\python -m pip install numpy einops
%TEMP%\qlv\Scripts\python -m pip install torch --index-url https://download.pytorch.org/whl/cpu
```
- 做法：每节写一个 `uXX_check.py`，把本节所有代码段依次跑一遍，把输出抄进代码块注释

### 5. 出测验（10 题）
- 正好 **10 题**，每题 **4 个选项**，考本节的**基础概念**（不考偏题、不考视频里的细枝末节）
- 题型搭配：概念理解、小计算（形状 / 数值）、辨析常见误区、「下面哪个说法**错误**」
- **正确答案分散在 A–D**，每个位置最多 4 次（`validate` 会检查）。写完看一眼答案序列，别有规律
- **讲解**：说明为什么对，并点出最有迷惑性的错误选项错在哪
- 涉及计算的答案都用代码验证
